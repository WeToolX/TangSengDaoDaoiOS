# 朋友圈接口对接修复

## 1. 背景

朋友圈发布、通知和评论链路存在客户端与服务端契约不一致、失败重试重复发布及资源上传异常。

## 2. 目标

修复已确认的朋友圈接口对接问题，保证发布重试幂等、可见范围参数有效、通知状态一致，并补齐现有接口对应的客户端交互。

## 3. 范围

涉及朋友圈发布、媒体上传、通知、评论和封面缓存；同时修改 iOS 与 IMServer 的接口响应对接。

## 4. 非目标

不新增朋友圈业务接口，不改变现有可见范围语义，不重写已有评论或媒体组件。

## 5. 影响模块

- iOS：`WuKongContacts` Moments、`WuKongBase` 上传客户端。
- 服务端：`IMServer/modules/moment`、必要的 `modules/file`。

## 6. 详细规则

- 同一发布操作的 `client_req_id` 在失败重试期间保持不变。
- 部分可见和不给谁看必须至少包含一个用户或标签；取消选择后恢复公开状态。
- 通知已读接口失败时保留客户端未读数。
- 通知详情字段必须由服务端返回并由 iOS 解析。
- 图片与视频封面使用唯一、可校验的上传路径，并传递真实媒体元数据。

## 7. 验收标准

- 断网后重试同一发布请求只产生一个 `post_id`。
- 取消可见范围选择不会上传媒体或提交空名单。
- 通知已读失败后红点不消失。
- 通知正文、动态预览和 mentions 能显示。
- 图片、视频、评论相关编译与接口测试通过。

## 8. 风险

真实网络重试、输入法、图片格式和缓存行为仍需真机验证；历史已上传的冲突封面无法自动恢复。
